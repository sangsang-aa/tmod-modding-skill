# 标准任务流程

> 先读 `confirmation.md`。本文件描述确认之后如何推进。

## 1. 澄清

确认：做什么内容、属于哪个模组、目标强度/行为、是否需要贴图与配方、是否多人。

## 2. 勘察

- 读现有模组代码，确认可复用/需兼容的部分。
- 在 `ExampleMod` 中找同类实现。
- **记录同类文件的目录层级、子目录划分、文件与贴图命名**，作为存放依据。

## 3. 方案

按 `confirmation.md` 的模板输出「需求理解 / 现状 / 逻辑 / 可选方向 / 影响范围 / 待确认」。

## 4. 等待确认

得到用户明确同意，并记下最终选定方向。未确认不得开工。

## 5. 实现

- 严格按确认方案执行；小步修改。
- 保持与周围代码的风格、命名、缩进一致。
- 只改约定范围内的文件；需要扩大范围时回到 `confirmation.md` §5。

## 6. 自检

- 编译/构建：见 `../build/build.md`。
- 目录与命名：见 `../project/layout.md`。
- 本地化：见 `../localization.md`。
- 召唤类：逐条对照 `../content/summon/index.md` 的强制清单。
- 注释：按 `tmod-code-comments` 技能。

## 7. 汇报

```text
【已改动】文件清单（含路径）+ 每个文件做了什么。
【实现要点】关键钩子/数据流/兼容性处理。
【验证结果】构建命令与结果；未验证的部分要明确说明。
【遗留项】需要用户提供的贴图/文本、待确认项、已知风险。
```

- 构建失败或环境不可用时，**如实说明**，不要谎报通过。
- 若执行中做过未在方案内的必要微调，一并列出。
