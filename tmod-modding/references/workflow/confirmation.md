# 确认流程（铁律）

> 本文件是 `tmod-modding` 的最高优先级规则。任何开发、修改、删除任务都先走这里。

## 1. 适用范围

收到以下任一类型的任务，都必须先完成「说明 → 确认」：

- 新增内容（物品、NPC、弹幕、方块、增益、配方、系统等）。
- 修改现有代码、数值、目录结构、资源配置。
- 删除文件或重构。
- 用户说「帮我做 X」「把 X 改成 Y」「修一下 X」。

## 2. 确认前允许 vs 禁止

**允许（只读）**

- 读取文件、搜索代码。
- 查看 `ExampleMod`、日志、构建输出。
- 运行不会修改仓库状态的查询命令。

**禁止**

- 写 / 改 / 删任何文件。
- 运行会改状态或触发构建/发布的命令。
- 以「先做一点试试」为由提前动手。

## 3. 必须输出的「方案说明」模板

```text
【需求理解】用一两句话复述要做什么，并点出任何歧义。
【现状勘察】相关文件/类/现有实现是什么（给出路径）。
【实现逻辑】打算改哪些文件、新增哪些类；使用哪些 tModLoader 类型与钩子；
          数据如何流转；与现有内容的兼容性/副作用。
【可选方向】如果有多种做法，列出 2-3 个方案，说明取舍并推荐其一。
【影响范围】新增/修改的文件清单及目录路径（对照 ExampleMod 的同类位置），
          是否需要新贴图、是否影响存档/多人同步。
【待确认】请用户明确回复选择哪个方向 / 是否开始。
```

## 4. 确认判定

- 只有用户**明确同意**（「确认」「可以」「就按方案 A」等）才开始执行。
- 用户未回复、回复含糊、或只问了别的问题时，继续等待或追问，**不要默认开工**。
- 用户说「你自己看着办 / 直接做」时可以执行，但执行后仍要汇报实际改动。

## 5. 偏离处理

执行中发现需要偏离已确认方案（新增文件、改接口、换方案、扩大范围）：

1. **立即停止**当前修改。
2. 说明偏离原因、影响范围、备选做法。
3. 再次获得确认后才继续。
